# SOMA_1deg

Wind-driven, bowl-shaped idealised basin. **62 × 62 × 31**, spherical polar,
`delX = delY = 1°`, `ygOrigin = 14.` so the domain spans **14°N–76°N**,
~3500 m deep, `dT = 1200 s`.

**The adjoint is serial-only** (`code_tap/SIZE.h`, one 62×62 tile; there is
no MPI adjoint variant, and nothing is copied into `code_tap/` at build time). **The forward
model is MPI**: `code/SIZE.h` is `nPx=2, nPy=2` over `sNx=sNy=31` = 4 ranks.

## Quick start

Run everything **from this directory**; `tools/machine_env.sh` supplies the
optfile, scratch root, MPI launcher and per-machine sbatch flags — nothing
needs exporting. Same workflow and same layout as DINO: the scripts live in
`scripts/` (since 2026-09-05) and are short definitions sourcing the shared
bodies in `tools/lib/`; what makes SOMA different is `scripts/setup_params.sh`.

```bash
# forward
./scripts/build_frd.sh                                   # -> build_frd/mitgcmuv
../../../tools/submit.sh scripts/submit_frd.sh           # 30 d, 4 ranks

# adjoint
./scripts/build_tapAdj.sh                                # -> build_tapAdj/mitgcmuv_tap_adj
../../../tools/submit.sh scripts/submit_tapAdj.sh        # 5 d, serial (the regression default)

# per-run overrides, exactly as in DINO — the tree stays clean
IMPACTS_DURATION_DAYS=30 ../../../tools/submit.sh scripts/submit_tapAdj.sh
IMPACTS_DURATION_DAYS=360 IMPACTS_ADJ_DUMP_FREQ_DAYS=30 \
    ../../../tools/submit.sh scripts/submit_tapAdj.sh
```

| Variable | Patches | Default (`frd` / `tapAdj`) |
| --- | --- | --- |
| `IMPACTS_DURATION_DAYS` | `endTime` (days × 86400 s; SOMA sets duration via `endTime`, not DINO's `nTimeSteps`) | `30` / `5` |
| `IMPACTS_MONITOR_FREQ_DAYS` | `monitorFreq` | `10` / `1` |
| `IMPACTS_ADJ_MONITOR_FREQ_DAYS` | `adjMonitorFreq` | — / `1` |
| `IMPACTS_ADJ_DUMP_FREQ_DAYS` | `adjDumpFreq` | — / `1` |
| `IMPACTS_TEST_CASE` | which variant is staged (machinery shared with DINO; SOMA has no `variants/` yet, so leave unset) | *(empty)* |

The committed defaults are the cheap regression configurations: the adjoint
default is the 5 d / all-frequencies-1 d configuration validated as run 31031
and re-run since as 31033 and 31076. 31031 itself was deleted in the 2026-09-03
scratch consolidation; **31033 is the surviving reference** — it was verified
bitwise against 31031 before the deletion, so a fresh run should match it.

## Build

| Script | Build directory | Executable |
| --- | --- | --- |
| `build_frd.sh` | `build_frd/` | `mitgcmuv` (forward only, 4 MPI ranks) |
| `build_tapAdj.sh` | `build_tapAdj/` | `mitgcmuv_tap_adj` (serial) |

Here `build_tapAdj.sh` is a real script that checkpoints every call. Since
2026-09-02 DINO's `build_tapAdj.sh` is a symlink to its profile-guided
`-nocheckpoint` build (`build_tapAdj_nocheckpoint.sh`) and its plain build is
`build_tapAdj_ckpAll.sh`; SOMA has no profile yet, so the bare name means the
plain adjoint here and the tuned one there. Its run token is nevertheless
`tapAdj_ckpAll`, DINO's vocabulary, so a tuned SOMA build can be told apart by
name when one exists. A SOMA port needs its own profiling run —
`tools/tapenade_profiling/mods_profile/` is setup-agnostic.

Both build scripts are definitions in `scripts/` sourcing the shared
`tools/lib/build_body.sh` (since 2026-09-05), as in DINO; the adjoint one sets
`PARALLEL=serial`, which is what selects `SERIAL_OPTFILE` and drops `-mpi`.
`scripts/setup_params.sh` carries what the bodies need to know about SOMA:
`DELTA_T=1200`, `DURATION_KEY=endTime`, `DAYS_PER_YEAR=360`, and the same
seven-entry `HOOK_CHECKS` list as DINO (the hooks are shared).

`build_tapAdj.sh` uses **stock** `genmake2` and the tree's stock Tapenade
options (since the 2026-08-31 hook conversion no generated file is
post-edited; since 2026-09-07 no hook file lives in this setup): the `ADJ*`
and `ADJetan` dump calls and the two adjoint-mode switches are generated by
Tapenade from the seven files of `../../mods_tapenade_hooks/`, the directory
shared with DINO that the build body lists first in `-mods` and whose
`flow_tap` it hands to Tapenade as a second external library (its README
maps each file to its place in the MITgcm tree; DINO's README section *"How
the Tapenade hooks work"* explains the mechanism). The rename to the upstream
names (2026-09-02) reproduced run 31033 bit for bit (run 31076, same 5-day
configuration: `fc`, all 32 `adxx_*`, all 61 `ADJ*` dumps and the 390-line
`%MON` stream); the move to the shared directory (2026-09-07) is validated
against 31076 the same way (the DINO `TODO.md` entry of that date has the
run). After `make`, the shared build body asserts, over the `HOOK_CHECKS`
list in `scripts/setup_params.sh`, that each generated `_B` call carries the
argument count the hand-written routine declares (a scalar field hook 7, a
vector pair 11, the etaN dump and the mode switches 5), that the compiled
`dummy_tap.f` carries its five `ADJ*` dump calls (they vanish silently if the
file loses its `AD_CONFIG.h` include), and that the hook sources link into
the shared directory. There is no `rawTapenade` control build any more — raw
output *is* the working configuration. SOMA carries the mode-switch hooks
since 2026-09-07 because the shared directory does; with its default
`data.autodiff` they change no parameter, and SOMA has no adjoint-viscosity
variant to switch.

**The conversion was a rescue, not just hygiene.** The previous mechanism's
frozen `forward_step_b.f_modified` had gone stale against the evolving tree
(274 diff lines vs freshly generated code), and the misaligned tape crashed
every c69m SOMA adjoint at the backward-sweep start (`integer divide by zero`
in `pkg/longstep`; runs 31029/31030). Run 31031 — the hook build — is the
**first successful c69m SOMA adjoint**: `fc` bitwise-identical to the crashed
baseline's forward value (`-9.21812947379697E-03`, 5 d), full finite
`ADJ*`/`adxx_*` output. The old-mechanism files are archived in
`00_archive/code_tap/` (see its README).

`build_frd.sh` builds the forward `code/` + `input/` pair (restored 2026-08-31
when the two setups' workflows were aligned; `code/packages.conf` drops the
c69f-era `timeave`, removed upstream in c69m).

Build directories symlink back into `code_tap/`, and no build script copies
anything into it (since 2026-09-02; `code_tap/SIZE.h` is the one serial
decomposition), so a build leaves `git status` clean. After editing a source,
re-run the build script rather than running bare `make` in a build directory.

## Run

Commands are in **Quick start** above; this section covers what the scripts do.

| Submit script | Uses build directory | Runs |
| --- | --- | --- |
| `submit_frd.sh` | `build_frd/` | 4 MPI ranks |
| `submit_tapAdj.sh` | `build_tapAdj/` | serial |

One script per mode, durations by `IMPACTS_DURATION_DAYS` — the same shape as
DINO (the five pre-made per-duration scripts this replaced are archived in
`00_archive/scripts/`; running two durations at once is now two submissions of
the same script with different overrides). Each is a definition in `scripts/`
sourcing the shared `tools/lib/submit_body.sh` (since 2026-09-05). Job names
are `SOMA_1deg_frd` / `SOMA_1deg_tapAdj` and name only the log file; run
directories follow DINO's convention, named from the build's `build_info.txt`:
`$SCRATCH_ROOT/SOMA_1deg_outputs/runs/{forward,adjoint}/SOMA_1deg_<run_token>_<duration>[_<tag>]_run<jobid>`
with `<run_token>` `frd` or `tapAdj_ckpAll` (no campaign subdirectory yet —
a handful of runs do not need one; add campaigns under `runs/adjoint/` the way
DINO did once there are more), with whole 360-day years labelled `<n>yr` and
everything else `<n>d`. The submit body also refuses a build directory whose
`run_token` is not the one the definition expects, and an executable that does
not match its record's `exe_md5`. Runs 31033, 31034 and 31076 predate the
token naming and keep their `SOMA_1deg_<mode>_<duration>_run<jobid>` names;
runs 31029–31031 predated the earlier renaming and kept their old
`pd_StP_srl_no-kpp-GM_*` / `test_*` directory names; all three of those were
deleted in the 2026-09-03 consolidation. The c69f-era `v4_soma_tapAdj_runs/`
tree is gone with them.

Each script patches the **staged** `data` in its own run directory, never the
tracked `input_tap/data`, so submitting leaves the working tree clean and two
queued jobs cannot race each other's namelist edits (the script body runs on
the compute node when the job *starts*).

Like DINO's, these scripts run under `set -e` and `set -x`. A model failure
therefore aborts the script before the "Run ended" line of `run_timing.txt`
is written — a truncated `run_timing.txt` is itself the failure marker; the
model's own output (`output_tap_adj.txt` / `output.txt`) and the `set -x` trace
in the log under `logs/` carry the details. (The archived per-duration scripts made the opposite
choice; it went away with them for consistency with DINO.)

A job leaves one log, `logs/<job-name>.<job-id>.out`, holding stdout and stderr
merged. It is gitignored, and the scripts run under `set -x`, so it is a full
trace of the staging steps — a staging failure shows up there rather than in the
model output on scratch, as does a SLURM-level kill (time limit, OOM, node
failure), which never reaches scratch at all. `tools/submit.sh` creates `logs/`
before submitting; sbatch fails a job at launch if that directory is missing.

Nothing prunes these — at ~8 KB apiece they are a record, not clutter. Use
`rm logs/*.out`, or `find logs -mtime +90 -delete`, whenever you want. Do not
delete the log of a *running* job: SLURM holds the file open, so the job keeps
writing to the unlinked inode, which loses the trace without freeing the space
until the job exits.

Unlike DINO there is no `adjVisc` variant here, and while the
`test_cases` mechanism is present (it is the shared body's), SOMA has a single
`input_tap/data` and no `variants/` directory yet.

## Files

| Path | Contents |
| --- | --- |
| `code/`, `input/` | forward model |
| `code_tap/`, `input_tap/` | adjoint model — adds `data.autodiff`, `data.cost`, `data.ctrl`, `data.grdchk` |
| `scripts/` | the four build and submit definitions (since 2026-09-05) and `setup_params.sh`; each definition sources a shared body in `tools/lib/` |
| `input_binaries/` | **untracked**, but regenerates: `python3 input/gendata.py` |
| `input_adj_binaries/` | **untracked.** `ones_64b.bin`, the uniform control weight |
| `00_archive/` | superseded files mirroring the live dirs (`scripts/` now also holds the five pre-made per-duration submit scripts and `code_tap/` the unused `the_model_main.F_ForTapProfile`) — nothing live reads it; has its own `README.md` |
| `.gitignore` | setup-local, ignores `*.out` / `*.err` |

For what the individual `code_tap/` sources and `input_tap/` namelists do, see
the **Reading the code** section of `../DINO_1deg/README.md` — the two setups
share the same structure and, since 2026-09-07, the very same hook files:
`../../mods_tapenade_hooks/`, one directory both setups build with, so no
hook file is in either `code_tap/` any more. What is left here is the
setup's configuration: `the_main_loop.F` (the tree file plus the binomial
checkpointing directive, byte-identical to DINO's), the cost function, the
decomposition and size headers, `packages.conf` and the option headers, each
the upstream c69m text with only `#define`/`#undef` toggles changed, so each
file vimdiffs cleanly against its counterpart.

The cost function is `code_tap/cost_atlantic_heat.F` with indices compiled in
(`isecbeg=1, isecend=62, jsec=27` — a zonal section at ~40°N — and
`kmaxdepth=21`). Changing the section means editing the file and rebuilding.

`useGrdchk = .TRUE.`, so every adjoint job also runs the finite-difference
gradient check and pays for it. As in DINO, whether its perturbation point sits
where the adjoint actually has sensitivity has not been checked here — see
"Verification status" in the root `README.md` before trusting its output.
KPP and GM/Redi are off in `input_tap/data.pkg`.

## A trap that cost real time

Two bugs sat here for a long time, each masking the other, and both are fixed:

1. `MITGCM_ROOT` in the build scripts pointed at `$SCRIPT_DIR/../MITgcm`, which
   resolves to `mysetups/MITgcm` — a directory that has never existed.
2. `code_tap/the_main_loop.F` included `GMREDI_TAVE.h`, a header **removed
   upstream in checkpoint69m**. DINO's copy has no such include, which is why
   only SOMA was affected. It sits inside `#ifdef ALLOW_GMREDI`, and
   `ALLOW_GMREDI` is defined because `packages.conf` pulls the `oceanic` group,
   so it is reached even though GM/Redi is disabled at runtime.

With (1) present, `genmake2` failed first and (2) was never visible. If this
setup starts failing again, check whether `code_tap/` still carries c69f-era
sources that reference something c69m has dropped.

The 2026-08-31 additive re-layout retired that class of failure for
`code_tap/`: every file there is now the c69m upstream source plus guarded
additions (the rebase of `the_main_loop.F` also restored upstream's
`COST_DRIVER` call, a runtime no-op in this configuration — verified bitwise,
run 31033 vs 31031). The same sweep caught the forward side's instance:
`code/packages.conf` still listed `timeave`, removed upstream in c69m, so the
forward model could not configure until that line was commented out. `code/`'s
other files remain c69f-era — the trap above still applies there.
